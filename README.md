# llmlab

> What the money and failure behaviour of an LLM gateway actually is, **measured**.
> Fault injection, a real agent over a real socket, one command, no network to the outside.

`llmgateway` claims a cap you cannot bypass, failover that tells provider errors from client
errors, and metering that never loses a response. `agentloop` claims a budget and a
deterministic replay. Claims become credible when somebody else can reproduce the numbers.
This repo drives the **real code of both** — one as a Cargo dependency, the other as a real
process — and publishes what happened.

```bash
make lab     # every scenario, including a real agent; writes reports/latest.{md,json}
make ci      # fmt + clippy -D warnings + the assertions
```

Scenarios 1–6 are in-process and take milliseconds. Scenario 7 runs a real `tsx` agent against
a real HTTP gateway and takes a few seconds, which is the price of measuring a wire.

## What it measures, and what came out

Every number is from `reports/latest.md`, regenerated by `make lab`. `cargo test` asserts the
invariants, so a regression fails the build instead of quietly changing the report.

| Scenario | What was measured | Why it matters |
|---|---|---|
| Cap holds before the spend | 10 requests against a 7 µUSD cap → 5 served, 5 rejected with `429`, provider called **exactly 5 times** | a rejected request never costs anything: the difference between a cap and a report |
| Reservation is pessimistic | estimate 3 µUSD per request, real cost 1 µUSD, surplus 2 µUSD | the cap rejects earlier than pure spending would — the measured price of checking first |
| Provider error | `503` → client gets `200` from the second provider; calls `provider-a: 1, provider-b: 1` | failover the client never notices |
| Client error | `400` → client gets `400`; `provider-b: 0` | an error of the client is not retried on someone else's account |
| Request that may already have been executed | provider dies after receiving → `502`, second provider `0`, spend `0` | retrying could charge twice, so it does not retry |
| Money vs metrics | 100 requests → spent **100 µUSD exactly**, while the `served` counter reports **0** at 1-in-1000 sampling | invoice on the money, dashboard on the counter |
| Streaming | forwarded as a stream, spend `0` | declared: usage of a stream arrives in its last chunk, which is never buffered |
| **The agent, over the wire** | `agentloop` (TypeScript, real budget, real trace) → HTTP → gateway → HTTP → provider: gateway metered **1 µUSD**, the agent's trace says **1 µUSD**, difference **0**, replay of the agent's trace identical | two independent implementations of the same arithmetic, in two languages, agreeing to the micro-dollar: that is what makes a runtime's budget reconcilable with a gateway's invoice |
| The cap, seen by an agent | the same run for a tenant whose budget is exhausted → gateway answers **429**, provider not called, agent's policy raises `PolicyError: ... 429 Too Many Requests: monthly budget exhausted` | a cap the runtime cannot talk its way around is a cap |

## How it works

```
                  scenarios 1-6                        scenario 7
        FakeProvider (→ test-provider)          agentloop (tsx, real process)
                    │                                    │ HTTP
                    ▼                                    ▼
             Router → Gateway::handle  ◄───────  llmgateway::http (axum)
                    │                                    │ HTTP
                    └──── Budget + Meter                 ▼
                                              test-provider (over HTTP)
```

Three properties, because a measurement you cannot trust is worse than no measurement:

- **the real code, not a model of it**: `llmgateway` comes in as a Cargo dependency,
  `Cargo.lock` pins the exact revision that was measured, and the agent is the real
  `agentloop` source, run by `tsx` from a sibling checkout;
- **no network to the outside**: the provider is a fake server on an ephemeral port, so nothing
  here can be slow, unavailable, or expensive, and the numbers are about this system;
- **invariants are assertions**: `cargo test` fails if a rejected request starts reaching a
  provider, if the cap stops holding, if a reservation is left pending, or if money stops being
  exact — and CI fails if the two accountings in scenario 7 disagree.

## What the lab found

- **The fake provider existed three times.** The lab's in-process one, the HTTP one scenario 7
  needs, and `llmgateway`'s test one: three copies of the same concept, and they had already
  drifted — the `model` echo below is what one copy learned and the others never did. The
  behaviours and both transports now live in one crate,
  [`test-provider`](https://github.com/paoValle/test-provider); each consumer keeps only the
  adapter onto its own trait. The one provider that stays separate on purpose is the wire-level
  one in `llmgateway`'s `tests/http.rs`, which needs a hang, the request headers and a hand-built
  streamed body — a fake shared with other projects should not model those.
- **A provider that does not echo `model` breaks `agentloop`'s replay.** The gateway records
  what the provider reported; without a `model` in the response the trace says `"unknown"` and
  the replay's recorded policy is labelled differently from the original run, so
  `replay().equal` becomes `false` for a run that is perfectly reproducible. The fake provider
  now echoes the model, like a real one. The finding is in `agentloop`'s column, not here.
- **`TenantSnapshot` had no tenant id**, so `/metrics` could not label anything. Found while
  adding the HTTP surface; fixed in `llmgateway`.
- **A comment in `llmgateway` contradicted its code**: it claimed the gateway does not judge a
  body without a model, while the code answers `400` itself. The behaviour is right (no model
  means no price and no routing, so there is nothing to forward to); the comment now says that.

## The fixtures are real runs, not hand-written JSON

`fixtures/*.jsonl` came out of `agentloop`'s `run()` with a scripted policy, a fake tool and no
network: the same scenario, three versions of it, written with `Trace.toJSONL()`. That is why
they contain the whole event stream — `run.start`, `policy.response`, `budget.settle`,
`tool.result`, `run.end` — and not only the fields this tool happens to read today:

| fixture | what changed | behaviour | money |
|---|---|---|---|
| `baseline.jsonl` | — | `b91a763c` | 10 µUSD |
| `pricier.jsonl` | twice the tokens, same decisions | `b91a763c` | 18 µUSD |
| `worse.jsonl` | the agent loops and never answers | `589e7bb9` | 3 µUSD |

`reports/agent-happy.jsonl` is the same idea at the top of the stack: the trace of the real
agent in scenario 7, as produced by the run — which makes it food for
[`traceset`](https://github.com/paoValle/traceset), the tool that turns traces into regression
tests.

## Usage

```bash
git clone https://github.com/paoValle/llmgateway.git ../llmgateway   # the dependency, as a sibling
git clone https://github.com/paoValle/agentloop.git  ../agentloop    # the agent for scenario 7
npm ci                                                              # tsx, for the agent
make lab     # writes reports/latest.md and reports/latest.json
make ci      # fmt + clippy + tests
```

Without the `agentloop` checkout, scenario 7 is **skipped loudly** in the report rather than
failing the lab: a lab that breaks because a sibling repository is missing teaches nothing.
`llmgateway` and `test-provider` are Cargo dependencies and need no checkout.

## Scope, declared

Not here, and not claimed:

- **latency.** Only money and failure semantics are measured. There is now a real socket, but a
  latency distribution needs a real provider and real load, and this lab has neither.
- **a real provider.** The provider is fake on purpose: a measurement that depends on somebody
  else's uptime is not a measurement you can run in CI.
- **multi-instance.** The gateway's state is in memory by design (ADR 0006), so this lab
  measures one instance. The second instance is where the interesting questions start.
- **the transport adapters' own correctness.** Byte-for-byte forwarding, streaming and the
  no-retry-after-timeout rule are covered by `llmgateway`'s own integration tests against a real
  HTTP server; this lab covers the system end to end.

## What I would do differently

- Scenario 7 shells out to `tsx` and parses one JSON line. It works, and it is the only place
  where a version skew between the two repositories would show up as a confusing failure rather
  than a clear one.
- `reports/latest.md` carries a timestamp, so every run dirties the tree. A `--check` mode that
  compares numbers against the committed ones would be the honest version of "the numbers
  changed".
